## 1. 背景与目标

### 1.1 背景与产品形态

把"下载、转码、合并"三个视频处理能力融合进**一个 Windows 桌面 GUI**（Rust + Tauri v2），形成一体化工具箱。核心形态决策：

1. **统一列表即工作台**：下载任务、下载产物、本地文件、处理任务全部在同一份列表里；下载 / 转码 / 合并是**作用于条目的动作**，不做分模块页面。
2. **元数据先行**：URL 或本地文件添加后，**先解析元数据**再进入可操作状态（下载前先解析标题/清晰度列表；本地文件先探测分辨率/编码/时长）。
3. **无流水线编排**：不做"下载→转码→合并"自动编排链；三个能力各自独立，由用户对条目逐个或批量触发。
4. **从零设计**：全新项目，不继承任何既有工程的代码；既有工具的经验已转化为本需求中的行为标准，不再另行罗列。

### 1.2 产品定位

一款面向个人/小团队的本地视频处理工具箱：

- **统一列表**：解析中/下载中/已下载/本地文件/处理中/失败，全部在一个列表里；筛选视图只做状态过滤。
- **下载能力**：B 站 / 抖音 / YouTube / X(Twitter) 等 1000+ 站点（yt-dlp 驱动）；下载完成自动后处理（画质上限、封面/元数据嵌入、音量归一化），完成后产物再执行本地解析（见 MD-06）。
- **转码能力**：批量转 H.265（Intel QSV 硬件加速自动降级），支持旋转、居中裁切竖屏、分辨率/码率封顶、音频增益、封面自动跟随；转码参数统一在设置界面配置，列表点"转码"直接按默认参数执行；输出回到列表或指定目录。
- **合并能力**：勾选多个条目按序拼接（同参直拼 / 异参先统一再拼）。

### 1.3 设计原则

1. **列表即工作台**：一切输入都进入同一列表；一切能力都以动作作用于条目。
2. **元数据先行**：任何条目进入可操作状态前，先完成元数据解析（URL 用站点解析，本地文件用 ffprobe 探测）；解析失败给明确原因与重试入口。
3. **从零设计、独立架构**：技术选型（Rust + Tauri v2）与模块划分按自身需求设计。
4. **本地优先**：全部本地处理、无任何网络上传、Cookie 仅本地存储；对外网络调用透明（见 §4 隐私透明）。
5. **失败安全**：不破坏原文件——写临时产物、校验成功后才原子替换；输出文件冲突原子预留命名。
6. **可维护可测试**：核心逻辑与界面分离，核心层可单元测试；CI 质量门禁严格。

### 1.4 成功标准（可量化）

- 解析：粘贴 URL 或添加本地文件 → 条目以"解析中"入列 → 元数据显示后变"已就绪"（已解析完成、可执行动作；URL 解析完成默认 5 秒后自动下载，倒计时期间点画质下拉可取消改手动）。
- 下载：已就绪下载条目 → 下载 → 自动后处理（画质上限/封面/元数据/音量）→ 产物本地解析（MD-06）→ 状态为"已完成"（不强制继续转码）。
- 转码：勾选 N 个条目一键批量转 H.265；QSV 可用时单文件速度 ≥ 3x 实时（1080P 参考）；OK/FAIL/SKIP 汇总正确。
- 合并：勾选多条目 → 排序 → 合并成功，输出可播放、进度可见、失败定位到具体文件。
- 工程：核心层单元测试 ≥ 30 个；CI 绿（Windows 服务器编译打包）；发布产物为单 EXE。

## 2. 目标用户与使用场景

### 2.1 目标用户

- 视频创作者 / 自媒体运营：从 B 站、抖音、YouTube 下载素材，压成 H.265 省空间，拼合多段素材。
- 个人收藏党：下载视频统一规范（1080P/HEVC/音量拉满），批量转码老视频。
- 手机录像用户：竖屏/横屏方向纠正（手动指定旋转方向）、批量转 H.265、多段拼接。

### 2.2 核心场景

1. **下载即标准**：粘贴 B 站/抖音链接 → 先解析（标题/清晰度/时长预览）→ 下载 → 自动选最佳 ≤1080P 格式 → 嵌封面元数据 → 音量归一化 → 已完成。
2. **批量瘦身**：把手机录像目录"添加目录"进列表 → 自动逐个解析 → 在封面缩略图上用旋转箭头手动指定方向（竖屏转正）→ 勾选 → 批量转码（H.265 + 音量增益）→ 输出到指定目录并回到列表。
3. **素材拼合**：从列表勾选多段素材 → 合并面板排序 → 合并（参数一致直拼，不一致先统一）。

### 3.2 元数据解析（前置步骤，P0）

> 任何 URL 或本地文件进入可操作状态前，必须完成元数据解析。

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| MD-01 | **URL 解析**：粘贴 URL 提交后，条目先以"解析中"入列；解析元数据：标题、时长、缩略图、可用清晰度/格式列表（含码率/大小估算）、是否合集/多 P；解析完成前不发起下载 | P0 |
| MD-02 | **本地文件解析**：添加本地文件/目录后，条目以"解析中"入列；用 ffprobe 探测：分辨率、编码、帧率、码率、时长、大小、音轨数、旋转标记、是否含封面，并用 volumedetect 探测音频音量（mean_volume / max_volume，供转码增益决策）；解析完成显示"已就绪" | P0 |
| MD-03 | 解析中状态展示：条目显示占位信息（文件名/URL）与"解析中"标签，可取消；URL 解析显示阶段进度（取信息→解析格式），本地解析通常秒级完成 | P0 |
| MD-04 | 解析结果作为后续动作默认参数：转码默认分辨率/码率/旋转依据解析结果；下载格式列表直接来自解析结果（MD-01） | P0 |
| MD-05 | 解析失败处理：条目标记失败并提示原因分类（网络不可达 / 需要登录 / 链接无效 / 非视频文件 / 探测失败）；提供"重新解析"与"移除"操作 | P0 |
| MD-06 | **下载完成产物解析**：URL 下载（含后处理）完成后，对产物文件执行与 MD-02 相同的本地解析（ffprobe + volumedetect），更新条目 meta、封面缩略图与音频音量；下载产物与本地文件一样具备完整转码/合并输入信息（分辨率/编码/帧率/音量等），可直接进入转码或合并 | P0 |
| MD-07 | **解析缓存**（cache.json 索引 + `config/cache/<hash>.jpg` 二进制）：URL 解析结果按 (host, 规范化 URL) 为 key 缓存（标题/时长/格式列表），默认 TTL 24h；缩略图落 `config/cache/<hash>.jpg` 单文件、cache.json 只存路径索引（避免每次"变更即原子写"重写整份 JSON）；"重新解析"强制刷新；yt-dlp 版本升级或站点 Cookie 变更后自动失效；设置-通用提供"清理解析缓存"入口 | P1 |

### 3.6 设置（P0）

| 分组 | 项 |
| --- | --- |
| 依赖 | yt-dlp / ffmpeg / ffprobe / deno 四个工具各自一行**路径输入框：留空＝使用系统 PATH（默认），填写则用指定路径**（含 `<exe 同级>\tools\` 托管，SHA-256 校验→暂存→版本命令+确定性媒体 fixture 校验→原子激活，失败保留当前版本）；**每个工具提供「下载」「更新」操作**（托管缺失时下载、有新版本时更新，均 SHA-256 校验后原子激活）；工具链联动：升级 yt-dlp 时校验 Deno 版本下限；PO-Token（POT）服务**默认启用**——YouTube 风控验证令牌（Proof-of-Origin Token），由 deno 运行 potoken 生成器产出，用于通过 YouTube 的机器人验证、降低 403/风控拦截概率 |
| 网络 | 代理地址（默认 socks5://127.0.0.1:10808，预设 Clash/V2RayN/SS 端口）；站点分流（站点列表，＋ 添加 / − 删除，按站点勾选是否走代理，其余直连） |
| Cookie | 目录固定为 `<exe 同级>\config\cookies\`（JSON 按 HOST 分文件，含 HttpOnly 等全字段，仅本地，不提供目录设置）；本页直接进行站点 Cookie 管理（列出已保存站点，查看 / 删除） |
| 下载 | 并发分片、重试次数、仅音频默认、播放列表默认、文件名模板（纯标题 / 标题+ID / UP主-标题 / 日期-标题，也用于转码/合并输出）、嵌入封面/元数据开关 |
| 转码 | MAXW/MAXH、码率封顶、默认编码器（自动 QSV→libx265 兜底；可强制 NVENC H.265 / AMF H.265 / libx265）、QSV low_power、旋转默认（按条目/统一指定）、保留封面；x265 CRF 固定 23（不提供配置） |
| 通用 | 默认输出目录（默认桌面）、碰撞命名策略（自动+1 / SKIP）、音量归一化（下载后处理与转码共用：按解析音量增益至峰值 0dBFS，接近满度不处理）、音量增益上限（24dB 默认）、并发任务数（默认 3；全局并行：下载/转码/合并共享；单任务下载分片见"下载-并发分片"）、启动时检查更新（默认开启）、历史上限（history.json 保留条数，默认 100、上限 200）、清理解析缓存 |

### 3.7 目录与存储约定（P0）

> 绿色便携：**所有产生的文件都存放在 exe 同级目录**，不写注册表、不依赖 %APPDATA%。

| 目录（exe 同级） | 内容 | 说明 |
| --- | --- | --- |
| `config/` | **所有固化内容（JSON + 二进制缓存例外）** | 唯一数据目录：config.json（用户设置）、history.json（列表/队列/历史，≤200 条，默认保留 100）、cookies/*.json（按 HOST 分文件）、cache.json（解析缓存索引）+ cache/（缩略图等二进制缓存，按 hash 命名，JSON 之外唯一例外）、ui.json（窗口/列状态） |
| `temp/` | 下载分片、中间产物、临时文件 | 按任务子目录隔离；任务结束清理或保留断点分片（可配）；提供"一键清理残留" |
| `tools/` | yt-dlp / ffmpeg / ffprobe / deno | 托管模式工具链安装目录（见 §3.6 依赖） |
| `logs/` | 运行日志（追加文本 .log） | 诊断用；日志属运行时记录而非固化数据，故不入 config |

规则：

- 所有需要固化的内容一律以 JSON 形式存于 `config/`，不散落到其它目录；JSON **原子写**（临时文件 + rename），启动时校验完整性，损坏则备份后回退默认；仅缩略图等二进制媒体落 `config/cache/`（按 hash 命名，为 JSON 原则的唯一例外）。
- Cookie 以 JSON 存于 `config/cookies/<host>.json`（含 name/value/domain/path/expires/httpOnly/secure/sameSite 全字段），与 DL-06 匹配。
- 下载产物输出到用户选择/默认输出目录（TC-11 不变），`temp/` 只承载中间过程文件。
- 删除/清理操作仅限本应用目录内的内容。

### 3.8 日志与诊断（P1）

- 每任务独立日志（最近 300 行），可复制；**无全局日志页**——日志按条目查看（底部状态栏不提供全局日志入口，见 §6.2）。
- 常见失败提示：B 站 412（提示放 cookie）、YouTube 403（检查 deno/代理/cookie/PO-Token）、X 强制登录、QSV 失败回落提示、解析失败原因分类（见 MD-05）。
- 依赖自检：yt-dlp/ffmpeg/ffprobe/deno 版本、QSV 可用性探测、代理连通性、可用硬件编码器列表。

### 5.3 关键设计问题（需求阶段需拍板的方向）

1. **统一条目模型**：MediaItem 覆盖"解析中 → 已就绪（已解析完成）→ 下载/转码/合并执行 → 已完成"的完整生命周期。
2. **合并双模式**：同参直拼 / 异参先统一再拼，临时产物放任务私有目录、结束清理。
3. **进度模型**：转码/合并先按文件粒度推进（P0），帧级进度后置（P1）。
4. **子进程取消**：任务取消需能终止 yt-dlp/ffmpeg 进程树（Windows `taskkill /T`），取消期间保持任务归属直到子进程退出（防竞态）。
5. **队列持久化**：任务状态落盘周期/时机（变更即写 vs 定时），与并发写冲突的处理（用于崩溃恢复，不依赖"无人值守"场景）；JSON 原子写（§3.7）。
6. **解析与执行分离**：元数据解析是独立子进程调用，解析结果缓存于条目（避免重复解析）；解析失败不阻塞列表其他操作。

### 6.2 交互约定

- 风格：浅色 Soft UI + 磨砂玻璃；中文字体；状态用颜色 + 文字标签。
- 拖拽：文件/URL 均可拖入窗口对应区域；列表内支持拖拽调整合并顺序（或面板内上下移动）。
- **手动旋转**：封面缩略图放大展示；两个旋转按钮（顺/逆时针 90°）放在**标题文字前**，点击后封面预览旋转 90°（**竖版旋转后同步缩放，实际高度不超行高**）、角度随条目保存；旋转角度以**封面缩略图右上角小角标**常驻反馈（仅角度 ≠ 0 时出现，如 `90°`，不占标题空间），替代被移除的标题行角度显示；设置"旋转默认"可选"按条目封面旋转"或统一指定方向（不自动纠正）；批量操作栏提供顺/逆时针旋转按钮（仅图标），对选中条目统一旋转。
- **转码直接执行**：行内/批量点击"转码"不弹确认窗，直接按设置界面（转码/输出分组）的默认参数开始；参数调整统一在设置界面完成。
- **格式选择**：URL 解析完成后（已就绪），画质/格式列显示当前选中格式并默认 5 秒后自动下载；倒计时期间点击画质下拉（格式选择弹窗）即取消自动下载，改为手动点"下载"执行；格式弹窗列出解析结果（清晰度/编码/大小），确定后按所选格式下载（见 DL-02）；本地文件该列只显示"源"元数据，无格式选择。
- **仅显示源元数据**：画质/格式列不显示"源/目标"标签与红/灰双态，只展示源解析元数据；字段全集（12 项）：容器格式、分辨率、编码器、视频码率、帧率、音频编码、音频采样率、音频码率、音轨数、最大音量、时长、大小，自动换行不截断（原型渲染 `MP4 · 4K · HEVC · 12Mbps · 60fps · AAC · 48kHz · 320k · 2轨 · −8.2dB · 05:32 · 35.6MB` 与该 12 项逐项对应、无重复项）；URL 已就绪行额外内联"格式选择"按钮（下载格式不影响此列展示）。
- **按条目日志**：每条记录操作列提供"日志"入口（**与其它操作按钮统一高度**），弹窗只显示该条目的完整处理日志时间线（解析→下载→后处理→转码→合并→完成/失败），支持清空/复制；底部状态栏不再提供全局日志入口。
- **底部状态栏**：队列（进行中/上限）与工具链就绪标识（yt-dlp / ffmpeg / deno / 硬件编码器如 QSV），不显示磁盘剩余。
- 元数据先行：URL/本地文件添加后条目立即以"解析中"出现；**本地文件/目录解析通常秒级完成，条目直接呈现"已就绪"**；解析完成自动更新为标题/画质/时长信息；名称副行固定为"站点/本地 · URL 或本地路径"（不显示解析摘要）。
- 失败行可点击展开错误详情（ffmpeg 尾部日志/解析错误）。
- "需要登录"状态显示"去登录"按钮 → 弹 WebView2 登录窗（**顶部中心"登录完成"按钮**：点击保存 Cookie 并关闭；YouTube 等 SPA 页面按钮与提示条每 800ms 自检重建，被页面脚本移除后最多 800ms 内重新出现）→ 自动续传。
- 空态引导：列表为空时给出"粘贴链接下载 / 添加本地文件"双入口引导。

### 6.3 状态与错误表达

- 状态色：解析中(紫)、已就绪(琥珀)、下载中(蓝)、后处理/转码/合并(青)、已完成(绿)、失败(红)、已取消(灰)、需要登录(橙)。
- 失败分级：可恢复（需要登录/412/403/解析重试）给操作指引；不可恢复显示错误摘要 + 日志查看。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 合并时输入参数不一致导致花屏/音画不同步 | 合并产物质量 | 模式 B 强制统一参数（转码后 concat）；合并前 ffprobe 对比并 UI 预警 |

| B 站 412 / X 强制登录 | 下载失败 | "需要登录"状态 + WebView2 登录续传；Cookie 引导文案 |
| 长路径/特殊字符（emoji 等） | 文件处理失败 | UTF-8 输出、文件名清洗、标题长度限制、路径参数化 |
| 转码/合并中途退出残留临时文件 | 磁盘占用/误判 | 任务私有临时目录 + 结束后清理 + 一键清理入口；临时产物后缀规避兜底误判；取消清理部分输出 |
| 并发写同一输出文件 | 覆盖/损坏 | 输出文件名唯一化（模板含 ID/时间戳）+ 原子预留碰撞安全命名（-1/-2 递增） |
| 统一列表条目增长导致性能下降 | 列表卡顿 | 虚拟滚动 / 分页 / 仅加载可见行（P1 起评估） |
| 队列持久化与运行中状态竞争 | 状态丢失/错乱 | 变更即原子写 + 启动恢复校验；写失败降级为内存态并提示 |
| 范围蔓延（播放器/帧级进度/AI 功能等） | 工期 | 按里程碑锁定范围，P1/P2 需求后置；AI/远程控制/插件体系明确不入本期 |

## 10. 打包与交付（仅单 EXE，无安装包）

- **CI（已确认）：使用 Windows 服务器编译打包** —— GitHub Actions **`windows-latest`** runner：
  - `build.yml`：push/PR 时在 Windows runner 上跑核心层单测 + Clippy（`-D warnings`）+ 依赖审计 + `cargo build --release` 产物校验。
  - `release.yml`：push tag `v*` 时在 Windows runner 上构建 release、打包 zip、发布 GitHub Release。
- **本地构建**：`pwsh ./scripts/build.ps1`（先跑核心层单测 → release），PowerShell 7（用户本机为 pwsh 7.6.5），与 CI 同构，保证本地与 CI 行为一致；**Linux 环境打包参考 `scripts/cross-build/README.md`**（cargo-xwin / zig 交叉编译出 MSVC 单 EXE），作为本地备用通道。
- **交付物**：**只交付一个 exe 文件，无安装包（不做 NSIS/不写注册表，绿色便携）**；GitHub CI release 负责在发布时套一层 zip。
- **交叉编译**（Linux 环境，参考 scripts/cross-build/README.md）仅作可选的本地备用通道，**不作为 CI 方案**；如需采用需先验证与 Windows runner 产物一致性。
