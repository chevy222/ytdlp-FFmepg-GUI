ytdlp-FFmpeg-GUI · 架构总览
需求阶段规划示意（v0.8）｜统一列表 + 元数据先行 + 下载/转码/合并三能力动作｜不做流水线编排｜全新项目，从零设计
一、主流程：添加 → 解析元数据 → 统一列表 → 能力动作
① 添加
粘贴 URL（B站/抖音/YouTube/X…）
添加本地文件 / 目录（拖拽或选择）
→
② 解析元数据（先行）
URL：yt-dlp -j（标题/时长/缩略图/清晰度列表）
本地：ffprobe + volumedetect（分辨率/编码/帧率/音轨/封面/音频音量）
下载完成产物同样本地解析（MD-06）· 失败分类提示 + 重新解析
→
③ 统一列表 · 待处理
同一份列表，勾选即可批量操作
状态筛选（全部/下载中/解析中/待处理/处理中/已完成/失败）
→
④ 能力动作（用户触发）
下载 · 转码 · 合并（行内或批量按钮）
执行中显示进度，完成后回到列表
二、统一列表 · 条目状态机（MediaItem）
解析中 待处理（已就绪） 下载中 后处理中 转码中 合并中 已完成 失败 已取消 需要登录
来源（站点/本地）显示在名称副行，不单独设列；解析结果作为下载格式列表与转码默认参数的来源。
三、三大能力（独立动作，不做自动编排）
下载（yt-dlp）
· 七级格式回落 + 排序串，MP4 容器统一
· 画质上限 MAX_H（短边），>上限自动降分辨率转码（QSV→libx265）
· 下载后处理：音量归一化 + 封面/元数据嵌入 + 产物本地解析（MD-06）
· 内置登录（WebView2：顶部中心"登录完成"按钮 + SPA 800ms 保活）、站点分流代理
· 时间范围下载 / 带宽限速（P1）
转码（ffmpeg）
· 编码器路线：QSV 全 GPU → 混合 → libx265（首文件协商锁定）
· 旋转 / 居中裁切竖屏 / 分辨率封顶 / 码率封顶 / 按解析音量增益（max_volume）
· 封面：自动跟随 / 添加自定义 / 不嵌入
· 预设档、碰撞安全命名（P1）
· 保留全部音轨 + hvc1 + faststart
合并（ffmpeg）
· 勾选多条目 → 面板排序 → 按序拼接
· 模式A 同参直拼（零重编码）/ 模式B 异参先统一再拼（差异预警）
· 输出 MP4/MKV，视频 copy/HEVC/H.264
· 可选音量归一化；产物作为新条目回到列表
四、工程架构（全新脚手架，核心层与界面分离）
界面层（UI）｜顶部输入区（URL/添加文件/目录）· 状态筛选 · 批量操作栏 · 统一媒体列表 · 转码面板（抽屉）· 合并面板（抽屉）· 设置弹窗 · 底部状态栏（原生 HTML/CSS/JS）
命令与状态层｜前后端命令桥接 · 全局状态（统一列表数据）· 登录窗 · CLI 入口/单实例转发
列表模型MediaItem、状态机、筛选视图、历史、队列持久化
元数据解析URL 解析（yt-dlp -j）、本地/下载产物探测（ffprobe + volumedetect）、失败分类、解析缓存
下载能力参数构造（格式回落/排序）、子进程运行、进度解析
转码能力编码器路线协商、旋转/裁切、码率/增益/封面、碰撞命名
合并能力参数对比、同参直拼 / 异参统一后拼、输出封装
探测 / 配置历史 / 站点Cookie / 依赖定位（工具链版本管理）（基础支撑）
存储约定全部文件在 exe 同级：config/（全 JSON 固化：config/history/cookies/presets/cache/ui）· temp/ · tools/ · logs/（绿色便携，见 §3.7）
五、打包与交付（Windows 服务器编译打包）
build.ps1（pwsh 7：单测→release）｜CI：GitHub Actions Windows 服务器（windows-latest）编译打包 —— build.yml（单测+Clippy+依赖审计+构建）、release.yml（tag v* 构建+打包 zip+发布）｜交付物：仅单 EXE、无安装包（不做 NSIS，绿色便携）｜Linux 环境打包参考 scripts/cross-build/README.md（cargo-xwin/zig 交叉编译，本地备用通道）
说明：需求阶段规划示意；本项目为全新项目、从零设计，不继承任何既有工程代码；不做流水线自动编排，下载/转码/合并为独立动作；URL 与本地文件添加后先解析元数据。
